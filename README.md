# もぐログ Web版

食事の記録と栄養の目安を確認できるWebアプリです。iOS版「もぐログ」をWebで動作する構成に作り替えたもので、**バックエンドから画面表示までGoで実装**しています（サーバーサイドレンダリング）。Mac / Xcode は不要で、ブラウザだけで動作確認できます。

## 機能

- **アカウント**: メールアドレス＋パスワードで新規登録、以降はログインして利用。記録はユーザーごとに分離されます
- **食事記録**: 内蔵食品データベース（114品目、日本食品標準成分表の代表値ベース）から検索して追加。定番メニューのテンプレート16種、よく記録する食品の候補表示に対応
- **写真から記録**: 写真をアップロードすると候補（テンプレート＋履歴）を提示します。※写真から料理を自動判定する機能はありません（後述）
- **目標管理**: Mifflin-St Jeor式で推奨カロリーを自動計算（安全下限：男性1500 / 女性1200 kcal）。ホーム画面で今日の摂取量・PFCバランス・残量を表示
- **履歴**: 月別カレンダー一覧と日別詳細
- **体重記録**: 一覧＋推移グラフ
- **CSV出力**: 全記録をCSVでダウンロード可能

### 写真の「解析」について（正直な仕様）

本アプリには画像認識モデルを組み込んでいないため、**写真から料理名や栄養素を自動で判定することはできません**。写真アップロード時は、定番メニューのテンプレートとご本人の記録履歴から候補を提示し、内容を確認・修正してから記録する方式です。画面上でもその旨を明示しています。

## 技術スタック

| 領域 | 採用 |
| --- | --- |
| 言語 | Go 1.27（標準ライブラリ中心） |
| ルーティング | net/http（Go 1.22+ のパターンマッチ） |
| 画面 | html/template によるサーバーサイドレンダリング＋最小限のJavaScript |
| DB | SQLite（modernc.org/sqlite、CGO不要のピュアGo実装） |
| パスワード | bcrypt（golang.org/x/crypto） |
| セッション | ランダムトークン＋SHA-256ハッシュをDBに保存、HttpOnly Cookie |
| デザイン | デジタル庁デザインシステム（DADS）の基本デザインを参考にしたローカルデザインシステム（キーカラー #0017C1、本文16px、コントラスト比4.5:1以上、フォーカスインジケーター等） |

参考デザイン: [デジタル庁デザインシステム – ローカルデザインシステム（スタイルガイド）](https://design.digital.go.jp/dads/guidance/local-design-system/)

## ローカル実行

```bash
go run .            # http://localhost:8080 で起動
```

環境変数:

| 変数 | 既定値 | 説明 |
| --- | --- | --- |
| `PORT` | `8080` | 待ち受けポート |
| `DATA_DIR` | `./data` | SQLiteファイルとアップロード写真の保存先 |
| `COOKIE_SECURE` | 無効 | `1` でセッションCookieに Secure 属性を付与（HTTPS公開時は必須） |

テスト:

```bash
go test ./...
```

## Docker

```bash
docker build -t moglog-web .
docker run -p 8080:8080 -v moglog-data:/data moglog-web
```

## AWS / GCP への公開メモ

コンテナイメージをそのまま使えます。

- **GCP Cloud Run**: `gcloud run deploy` でデプロイ可能。ただしSQLiteとアップロード写真はローカルファイルのため、永続化にはボリュームマウント（Cloud Storage FUSE等）か、将来的なDB移行（Cloud SQL / PostgreSQL化）が必要です。まずは検証用に `--max-instances=1` ＋ ボリューム構成が現実的です
- **AWS**: App Runner / ECS Fargate ＋ EFS を `/data` にマウントする構成が相当します。ALB配下では `COOKIE_SECURE=1` を設定してください
- 本番ではHTTPS終端の後ろで動かし、`COOKIE_SECURE=1` を必ず有効化してください

将来の拡張候補: PostgreSQL対応（DB層の差し替え）、パスワードリセット、メール確認、PWA化。

## ディレクトリ構成

```
main.go        起動・ルーティング・認証ミドルウェア
handlers.go    画面ハンドラ一式
auth.go        パスワード/セッション/レート制限
store.go       SQLite アクセス
domain.go      栄養計算・目標カロリー計算（Mifflin-St Jeor）
catalog.go     食品DB・テンプレート読み込みと候補提示
internal/data/ 食品データ(114品目)とテンプレート(16種)のJSON
web/templates/ HTMLテンプレート
web/static/    CSS（DADS風） / JavaScript
```

## ライセンス・データ出典

栄養値は文部科学省「日本食品標準成分表（八訂）増補2023年」の代表値をもとにした概数です。実際の食品とは差が生じるため、アプリ内では推定値として表示します。
